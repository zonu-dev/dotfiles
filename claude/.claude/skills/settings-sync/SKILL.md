# settings-sync

プロジェクトの `settings.local.json` とグローバルの `settings.json` の権限ルールを比較し、重複削除・グローバル移行を支援する。

処理の流れ: 設定読み込み → 重複検出・削除 → 移行候補の分類・提示 → 移行実行 → 結果表示

## 1. 設定ファイルの読み込み

以下の2ファイルを読み込む:

- **グローバル**: `~/.claude/settings.json` の `permissions`（`allow` / `deny` / `ask`）
- **プロジェクト**: カレントプロジェクトの `.claude/settings.local.json` の `permissions`（同上）

プロジェクト側に `.claude/settings.local.json` が存在しない場合、その旨を伝えて終了する。

## 2. 重複ルールの検出と削除

`settings.local.json` の各権限ルールについて、グローバル `settings.json` に同一エントリが存在するか確認する。

**重複判定**: 文字列が完全一致するルール。同じカテゴリ（allow/deny/ask）内での一致を確認する。

重複が見つかった場合:
- 一覧をユーザーに表示する
- ユーザーの確認後、`settings.local.json` から重複エントリを削除する
- `permissions` 配下のキーが空配列になった場合、そのキー自体を削除する

重複がない場合はその旨を伝え、次のステップへ進む。

## 3. 移行候補の分類と提示

`settings.local.json` にのみ存在するルールを以下の3カテゴリに分類し、テーブル形式で提示する:

#### 分類基準

**グローバル移行推奨**:
- 汎用的なコマンド（`Bash(grep *)`, `Bash(tail *)` 等、多くのプロジェクトで使う）
- 広く使われるドメインへの `WebFetch`（`npmjs.com`, `docs.python.org` 等）
- プロジェクト固有でないセキュリティルール（`deny` の汎用パターン）

**要検討**:
- 特定の技術スタックに紐づくルール（フレームワーク固有のCLI等）
- 利用頻度が不明なルール

**プロジェクト固有（移行非推奨）**:
- プロジェクト固有のドメインへの `WebFetch`
- プロジェクト固有のツールやスクリプト
- `additionalDirectories` などの非権限フィールド

#### 表示フォーマット

```
| カテゴリ | ルール | 分類 | 理由 |
|----------|--------|------|------|
| allow    | Bash(grep *) | グローバル移行推奨 | 汎用的なコマンド |
| allow    | WebFetch(domain:example.com) | プロジェクト固有 | プロジェクト専用ドメイン |
```

分類結果をテーブルで提示した後、`AskUserQuestion` で移行対象を確認する:
- 質問1: 「グローバル移行推奨」のルールをまとめて移行してよいか
- 質問2: 「要検討」のルールについて個別に移行可否を判断（ルールごとに質問）
- 「プロジェクト固有」のルールは移行対象外として扱う（ユーザーが希望すれば変更可）

## 4. 移行の実行

ユーザーの指示に従い:

1. 選択されたルールを `~/.claude/settings.json` の該当カテゴリに追加する
2. 移行したルールを `.claude/settings.local.json` から削除する
3. 空になったカテゴリキーを削除する
4. `permissions` 自体が空オブジェクトになった場合は、`settings.local.json` から `permissions` キーを削除する（他のフィールドが残っていれば保持）

**編集時の注意**:
- JSONのフォーマット（インデント2スペース）を維持する
- 既存のソート順を維持する（末尾に追加）
- `permissions` 以外のフィールド（`additionalDirectories` 等）は変更しない
- **Bash権限の記法**: `Bash(tail *)` のスペース形式が公式推奨。`Bash(tail:*)` のコロン形式はレガシーで廃止予定。移行時にコロン形式のルールを見つけた場合はスペース形式に正規化してからグローバルに追加する。ローカルにコロン形式、グローバルにスペース形式で同じコマンドが存在する場合は、形式違いの実質的な重複としてユーザーに提示する

## 5. 結果の表示

移行完了後、以下を表示する:

```
設定の同期が完了しました

重複削除: N件
グローバルに移行: N件
プロジェクトに残留: N件

変更されたファイル:
- ~/.claude/settings.json
- .claude/settings.local.json
```
